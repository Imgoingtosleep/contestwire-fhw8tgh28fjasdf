# เปิดเว็บให้คนนอกเข้าดู โดยยังไม่ต้องมีโดเมน (Tunnel)

ชุดนี้ทำให้คนอื่นเปิดเว็บของเราจากที่ไหนก็ได้ผ่าน `https://` ภายในไม่กี่นาที
โดย **ไม่ต้องซื้อโดเมน ไม่ต้องเช่าเซิร์ฟเวอร์ และไม่ต้องสมัครบัญชีใด ๆ**

หลักการคือรัน agent ตัวเล็ก ๆ อยู่ข้าง ๆ เว็บ แล้วให้มันเปิดการเชื่อมต่อ
**ออกไป** หาเครือข่ายปลายทางเอง ปลายทางจึงส่งผู้เข้าชมย้อนกลับเข้ามาได้
โดยที่เครื่องเราไม่ต้องเปิดพอร์ตรับเข้าเลยแม้แต่พอร์ตเดียว และใบรับรอง TLS
ถูกจัดการให้ที่ปลายทาง เราจึงไม่ต้องยุ่งกับ certbot

> ต่างจาก [DEPLOYMENT.md](./DEPLOYMENT.md) ที่เป็นการวางบน VPS จริง
> พร้อมโดเมนของตัวเองและใบรับรองที่ต่ออายุเอง — เลือกใช้อย่างใดอย่างหนึ่ง

---

## 1. เริ่มใช้งาน

```bash
cp .env.tunnel.example .env.tunnel
nano .env.tunnel          # แก้ POSTGRES_PASSWORD และ JWT_SECRET เป็นค่าสุ่ม
chmod 600 .env.tunnel
```

สุ่มค่าลับด้วย:

```bash
openssl rand -base64 36   # POSTGRES_PASSWORD
openssl rand -base64 48   # JWT_SECRET
```

จากนั้นสตาร์ตทั้งชุด (ครั้งแรกจะใช้เวลา build React สักพัก):

```bash
docker compose -f docker-compose.tunnel.yml --env-file .env.tunnel up -d --build
./scripts/tunnel-url.sh
```

`tunnel-url.sh` จะพิมพ์ URL สาธารณะออกมา เช่น

```
https://contribution-databases-male-cheats.trycloudflare.com
```

ส่ง URL นี้ให้ใครก็ได้เปิดดูทันที ทั้งหน้าเว็บและ `/api` วิ่งผ่านโฮสต์เดียวกัน

ตรวจว่าทุกอย่างพร้อม:

```bash
curl -s "$(./scripts/tunnel-url.sh)/api/health"
```

ต้องได้ `"database":"PostgreSQL connected"` กลับมา

## 2. ชุดนี้ประกอบด้วยอะไร

| Service | หน้าที่ | เปิดพอร์ตออกโฮสต์ |
|---|---|---|
| `postgres` | ฐานข้อมูล | ไม่ |
| `backend` | Express API | ไม่ |
| `web` | nginx เสิร์ฟไฟล์ build ของ React + ส่งต่อ `/api` ไป backend | ไม่ |
| `cloudflared` | เปิด tunnel ออกไปหาปลายทาง | ไม่ |

ทางเข้าเดียวคือตัว tunnel เอง — `docker ps` จะเห็นว่าไม่มีคอลัมน์ port ที่ผูกกับ
โฮสต์เลยสักตัว ไฟร์วอลล์ของเครื่องจึงไม่ต้องเปิดอะไรเพิ่ม

ไฟล์ที่เกี่ยวข้อง:

- `docker-compose.tunnel.yml` — นิยาม 4 service ข้างบน
- `nginx/tunnel.conf.template` — คอนฟิก nginx แบบ HTTP อย่างเดียว (TLS จบที่ปลายทางแล้ว)
- `.env.tunnel.example` — เทมเพลตค่าคอนฟิก
- `scripts/tunnel-url.sh` — ถาม URL ปัจจุบัน

ชุดนี้ตั้งชื่อโปรเจกต์เป็น `contestwire-tunnel` แยกจาก dev stack จึงมีคอนเทนเนอร์
เครือข่าย และฐานข้อมูลของตัวเอง รันคู่กับ `docker compose up` ตอนพัฒนาได้พร้อมกัน
โดยไม่ชนกัน (แต่ข้อมูลในฐานข้อมูลคนละก้อน)

## 3. ข้อจำกัดที่ต้องรู้

| เรื่อง | รายละเอียด |
|---|---|
| **URL เปลี่ยนทุกครั้ง** | รีสตาร์ต `cloudflared` เมื่อไหร่ได้ชื่อใหม่เสมอ — เหมาะกับส่งให้ดูงานชั่วคราว ไม่เหมาะกับใช้จริง |
| **ไฟล์อัปโหลดใหญ่สุด 100 MB** | เป็นลิมิตของ tunnel แบบฟรี ตั้ง `MAX_UPLOAD_SIZE_MB` เกินกว่านี้ไม่ช่วย ไฟล์ใหญ่กว่านั้นต้องใช้ `POST /api/upload/presign` แล้วให้เบราว์เซอร์อัปตรงเข้าที่เก็บไฟล์ ซึ่งไม่วิ่งผ่าน tunnel |
| **ไม่มี SLA** | tunnel แบบไม่ล็อกอินเป็นบริการทดลอง อาจช้าหรือหลุดได้ |
| **ใครมี URL ก็เข้าได้** | ไม่มีการยืนยันตัวตน อย่าใส่ข้อมูลจริงที่เป็นความลับลงฐานข้อมูลชุดนี้ |

## 4. คำสั่งที่ใช้บ่อย

```bash
C="docker compose -f docker-compose.tunnel.yml --env-file .env.tunnel"

$C ps                     # สถานะทุก service
$C logs -f cloudflared    # ดู URL และการเชื่อมต่อ
$C logs -f backend        # ล็อกของ API
$C up -d --build          # อัปเดตหลังแก้โค้ด
$C down                   # ปิด (ข้อมูลใน volume ยังอยู่)
$C down -v                # ปิดพร้อมลบฐานข้อมูลทิ้ง
```

> แก้ค่า `REACT_APP_*` เมื่อไหร่ต้องใส่ `--build` เสมอ เพราะ React ฝังค่าพวกนี้
> ตั้งแต่ตอน build ไม่ได้อ่านตอนรัน

## 4.1 ปิดแล้วกลับมาเปิดใหม่รอบหน้า

ตั้งตัวย่อไว้ใช้ก่อน (ต้องอยู่ในโฟลเดอร์โปรเจกต์ และตั้งใหม่ทุกครั้งที่เปิด
เทอร์มินัลใหม่):

```bash
C="docker compose -f docker-compose.tunnel.yml --env-file .env.tunnel"
```

**ปิด** — เลือกอย่างใดอย่างหนึ่ง

```bash
$C stop     # หยุดไว้เฉย ๆ คอนเทนเนอร์ยังอยู่ กลับมาเปิดเร็วที่สุด
$C down     # ลบคอนเทนเนอร์ทิ้ง แต่ volume ฐานข้อมูลยังอยู่ครบ
$C down -v  # ลบฐานข้อมูลทิ้งด้วย เริ่มใหม่หมด
```

**เปิดใหม่**

```bash
$C start                 # ถ้าปิดด้วย stop
$C up -d                 # ถ้าปิดด้วย down (หรือไม่แน่ใจว่าปิดด้วยอะไร)
$C up -d --build         # ถ้าแก้โค้ดหรือแก้ค่า REACT_APP_* ระหว่างนั้น
./scripts/tunnel-url.sh  # ขอ URL ใหม่ — ทำทุกครั้ง
```

> **URL จะเป็นคนละอันเสมอ** ทุกครั้งที่ `cloudflared` เริ่มใหม่ ลิงก์เดิมที่เคย
> ส่งให้ใครไว้จะใช้ไม่ได้อีก ต้องรัน `tunnel-url.sh` แล้วส่งลิงก์ใหม่ไปให้
> (ถ้าอยากได้ลิงก์ที่คงที่ ต้องมีโดเมนแล้วทำตามข้อ 5)

`up -d` เฉย ๆ ไม่ build ใหม่ ถ้าอิมเมจมีอยู่แล้วจะขึ้นภายในไม่กี่วินาที
ที่นานคือรอบแรกกับตอนใส่ `--build` เพราะต้อง build React ใหม่

**อยากได้ URL ใหม่โดยไม่ปิดทั้งชุด** (เช่นลิงก์เดิมหลุดออกไปที่ไม่ควร):

```bash
$C restart cloudflared && ./scripts/tunnel-url.sh
```

**ลืมว่าเปิดค้างไว้หรือเปล่า**

```bash
$C ps                    # ว่างเปล่า = ปิดอยู่
docker ps | grep rs_tunnel
```

## 5. เมื่อซื้อโดเมนมาแล้ว

ต่อยอดจากชุดเดิมได้เลย ไม่ต้องรื้อ เปลี่ยนแค่ให้ tunnel ผูกกับโดเมนจริง
URL จะได้คงที่:

1. สมัครบัญชีกับผู้ให้บริการ tunnel (แผนฟรีพอ) แล้วเพิ่มโดเมนเข้าไป
2. ที่หน้าจัดการโดเมนของผู้ให้บริการที่เราซื้อมา เปลี่ยน **nameservers**
   เป็นของผู้ให้บริการ tunnel — โดเมนยังอยู่ที่เดิม แค่ย้ายการจัดการ DNS
   (ตรวจด้วย `dig +short NS example.com` ใช้เวลากระจาย 5 นาที – 24 ชม.)
3. สร้าง tunnel แบบ *remotely-managed* จะได้ **token** มาหนึ่งชุด
4. ตั้ง public hostname ในหน้าเดียวกัน: `example.com` และ `www.example.com`
   ชี้ไปที่ `http://web:80` (เรคคอร์ด DNS ถูกสร้างให้อัตโนมัติ)
5. ใส่ token ลง `.env.tunnel` ที่ `TUNNEL_TOKEN=` แล้วสลับบรรทัด `command`
   ของ service `cloudflared` ใน `docker-compose.tunnel.yml` ไปเป็นแบบมี token
   (คอมเมนต์บอกไว้ให้แล้วในไฟล์)
6. แก้ `CORS_ORIGIN` ใน `.env.tunnel` เป็น `https://example.com,https://www.example.com`
   แล้ว `$C up -d --build`

ตั้งค่าฝั่งผู้ให้บริการเพิ่มอีกสองอย่าง: โหมด TLS เป็น **Full** และเปิด
**Always Use HTTPS**

> ถ้าอยากย้ายไปวางบน VPS ของตัวเองพร้อมใบรับรองที่จัดการเอง (ไม่พึ่ง tunnel)
> ให้ดู [DEPLOYMENT.md](./DEPLOYMENT.md) แทน — คนละชุด compose กัน

## 6. แก้ปัญหา

**`tunnel-url.sh` ไม่คืน URL**

```bash
$C logs cloudflared | grep -i trycloudflare
```

ถ้าเห็นบรรทัด `Requesting new quick Tunnel...` แต่ไม่มี URL ตามมา แปลว่าเครื่อง
ออกอินเทอร์เน็ตไม่ได้ หรือ UDP/443 (QUIC) ถูกบล็อก ลองใหม่อีกครั้งด้วย
`$C restart cloudflared`

**เปิด URL แล้วขึ้น 502**

`web` ยังไม่พร้อม หรือ build React ล้มเหลว — ดู `$C logs web` และ `$C ps`

**หน้าเว็บขึ้นแต่ยิง API ไม่ผ่าน**

ตรวจว่า `REACT_APP_API_URL` ใน `.env.tunnel` เป็น `/api` (ไม่ใช่
`http://localhost:9100/api`) ถ้าเพิ่งแก้ ต้อง `$C up -d --build` ใหม่

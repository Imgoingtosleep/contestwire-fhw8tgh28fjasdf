# ขั้นตอนติดตั้ง — จากซื้อโดเมนและเซิร์ฟเวอร์ จนเว็บขึ้นจริง

เอกสารนี้เป็น **ลำดับขั้นตอนและตารางเทียบค่า** ว่าของที่ได้จากผู้ให้บริการ
เอาไปใส่ตรงไหน ส่วนคำสั่งเต็มของแต่ละขั้นอยู่ใน [`DEPLOYMENT.md`](./DEPLOYMENT.md)

> **สรุปก่อนเริ่ม:** ไฟล์ที่ต้องแก้มีไฟล์เดียวคือ `.env.production` ซึ่งสร้าง
> บนเซิร์ฟเวอร์ ไฟล์อื่นอ่านค่าต่อจากไฟล์นี้เองทั้งหมด

> **ยังไม่มีโดเมนหรือเซิร์ฟเวอร์ แต่อยากให้คนอื่นเปิดดูได้วันนี้เลย**
> ใช้ [`TUNNEL.md`](./TUNNEL.md) แทน — ได้ URL `https://` ภายในไม่กี่นาที
> ไม่ต้องซื้ออะไรและไม่ต้องสมัครบัญชี

---

## 1. ของที่ได้จากผู้ให้บริการ และเอาไปใช้ตรงไหน

### จากโดเมน

ไม่ได้ไฟล์อะไร ได้แค่ชื่อโดเมนกับสิทธิ์เข้าหน้าจัดการ DNS

| ได้อะไรมา | เอาไปใช้ที่ไหน |
|---|---|
| ชื่อโดเมน เช่น `example.com` | บรรทัด `DOMAIN` ใน `.env.production` |
| สิทธิ์เข้าหน้า DNS Management | ใช้ตั้งเรคคอร์ด `A` (ข้อ 3) |

### จากเซิร์ฟเวอร์ VPS

| ได้อะไรมา  | เอาไปใช้ที่ไหน |
| --------- | ------------ |
| **IPv4 address** เช่น `203.0.113.45` | ใส่ในเรคคอร์ด DNS + คำสั่ง `ssh` — **ไม่ได้อยู่ในไฟล์ใดของโปรเจกต์** |
| รหัสผ่าน root หรือ SSH key | ใช้ล็อกอินครั้งแรกเท่านั้น |
| hostname ที่ผู้ให้บริการตั้งให้ | ไม่ต้องใช้ |
| ตัวเลือกระบบปฏิบัติการ | เลือก Ubuntu 22.04 LTS แบบไม่มีแผงควบคุมสำเร็จรูป |

> **จุดที่เข้าใจผิดกันบ่อย:** IP ของเซิร์ฟเวอร์ไม่ได้เขียนอยู่ในโค้ดเลย
> การเชื่อมโดเมนเข้ากับเซิร์ฟเวอร์เกิดขึ้นที่ DNS ไม่ได้เกิดในไฟล์คอนฟิก

> เลือกเครื่องที่เป็น Ubuntu เปล่า ๆ เพราะแผงควบคุมสำเร็จรูป (cPanel, Plesk)
> จะยึดพอร์ต 80 และ 443 ไว้ ทำให้ nginx ของโปรเจกต์จับพอร์ตไม่ได้

## 2. เช็กลิสต์ตามลำดับ

ทำเรียงจากบนลงล่าง ห้ามข้ามข้อ 3 ไปข้อ 6

- [ ] **1. ซื้อโดเมนและ VPS** — จด IPv4 ของ VPS ไว้
- [ ] **2. เตรียมเซิร์ฟเวอร์** — สร้างผู้ใช้ที่ไม่ใช่ root, ปิดล็อกอินด้วยรหัสผ่าน,
      เปิดไฟร์วอลล์เฉพาะ SSH/80/443, ติดตั้ง Docker
      → [DEPLOYMENT.md ข้อ 2](./DEPLOYMENT.md)
- [ ] **3. ตั้ง DNS** — เพิ่มเรคคอร์ด `A` สองรายการ (ตารางข้อ 3 ด้านล่าง)
- [ ] **4. รอ DNS กระจาย** — `dig +short example.com` ต้องคืน IP ของ VPS
      ปกติ 5 - 30 นาที
- [ ] **5. นำโค้ดขึ้นเครื่อง** — `git clone` แล้ว `cd` เข้าโฟลเดอร์
- [ ] **6. สร้าง `.env.production`** — คัดลอกจากแม่แบบแล้วกรอกค่า (ตารางข้อ 4)
- [ ] **7. ขอใบรับรอง TLS แบบทดสอบ** — ตั้ง `ACME_STAGING=true` แล้วรัน
      `./scripts/init-ssl.sh`
- [ ] **8. ขอใบรับรองจริง** — เปลี่ยนเป็น `ACME_STAGING=false` แล้วรันสคริปต์ซ้ำ
- [ ] **9. สตาร์ตทั้งระบบ** —
      `docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build`
- [ ] **10. ตรวจผล** — เปิด `https://example.com` และ `curl https://example.com/api/health`

## 3. เรคคอร์ด DNS ที่ต้องตั้ง

| Type | Name | Value | TTL |
|---|---|---|---|
| `A` | `@` | IPv4 ของ VPS | 600 |
| `A` | `www` | IPv4 ของ VPS | 600 |

**ลบของเดิมออกก่อน** — ผู้ให้บริการโดเมนมักตั้งเรคคอร์ดมาให้ตอนซื้อ โดยเฉพาะ
`A` ของ `@` ที่ชี้ไปหน้า parking และ `CNAME` ของ `www` ทั้งสองอันจะทับกับที่เราตั้ง

**อย่าเปิด Domain Forwarding / URL Redirect** เพราะจะไปทับเรคคอร์ด `A`
ทำให้ขอใบรับรองไม่ผ่าน

## 4. ค่าใน `.env.production` มาจากไหนบ้าง

```bash
cp .env.production.example .env.production
nano .env.production
chmod 600 .env.production
```

| ตัวแปร | ค่ามาจากไหน | ตัวอย่าง |
|---|---|---|
| `DOMAIN` | ผู้ให้บริการโดเมน | `example.com` (ไม่ใส่ `https://` ไม่ใส่ `www`) |
| `ACME_EMAIL` | อีเมลของคุณเอง | `you@example.com` |
| `ACME_STAGING` | ตั้งเอง | `true` ตอนลอง แล้วเปลี่ยนเป็น `false` |
| `POSTGRES_USER` | ตั้งเอง | `rsadmin` |
| `POSTGRES_PASSWORD` | สุ่มเอง | `openssl rand -base64 36` |
| `POSTGRES_DB` | ตั้งเอง | `news_contest_db` |
| `JWT_SECRET` | สุ่มเอง | `openssl rand -base64 48` |
| `CORS_ORIGIN` | ได้จาก `DOMAIN` | `https://example.com,https://www.example.com` |
| `MAX_UPLOAD_SIZE_MB` | ตั้งเอง | `50` |
| `R2_*` (5 ตัว) | **ผู้ให้บริการที่เก็บไฟล์ ไม่ใช่เจ้าของโดเมน** | จากหน้า API token ของบริการนั้น |
| `REACT_APP_API_URL` | **ปล่อยเป็น `/api`** | อย่าเปลี่ยนเป็น URL เต็ม |
| `REACT_APP_SITE_NAME` | ตั้งเอง | `โตโยต้า ถนนสีขาว` |

### ทำไม `REACT_APP_API_URL` ต้องเป็น `/api`

เพราะ frontend เรียก API ผ่านโดเมนเดียวกัน โดยมี nginx เป็นตัวส่งต่อไป backend
ให้ในเครือข่ายภายใน ผลคือไม่ต้องเปิดพอร์ต backend ออกอินเทอร์เน็ต ไม่ต้องตั้ง
subdomain แยก และไม่เจอปัญหา CORS หรือ mixed content

ถ้าเปลี่ยนเป็น `https://api.example.com/api` จะต้องตั้ง DNS เพิ่ม ตั้ง server
block เพิ่ม และขอใบรับรองเพิ่ม โดยไม่ได้ประโยชน์อะไรกับขนาดงานนี้

## 5. ไฟล์ไหนต้องแก้ ไฟล์ไหนห้ามแก้

| ไฟล์ | ต้องแก้ไหม |
|---|---|
| `.env.production` | **ใช่ — ไฟล์เดียวที่ต้องกรอกค่า** |
| `docker-compose.prod.yml` | ไม่ต้อง อ่านค่าจาก `.env.production` |
| `nginx/prod.conf.template` | ไม่ต้อง เติม `${DOMAIN}` ให้ตอนคอนเทนเนอร์สตาร์ต |
| `docker/Dockerfile.*.prod` | ไม่ต้อง |
| `nginx/default.conf` | **ไม่ต้อง — เป็นเทมเพลตเก่าที่ไม่มีอะไรเรียกใช้แล้ว** |
| `.env` / `.env.example` | ไม่ต้อง เป็นของฝั่ง dev |
| `frontend/src/utils/api.js` | ไม่ต้อง ค่า `localhost` เป็นค่าสำรองตอน dev เท่านั้น |

## 6. ตรวจว่าสำเร็จแล้วจริง

```bash
# ทุก service ต้องขึ้น running
docker compose -f docker-compose.prod.yml --env-file .env.production ps

# ต้องได้ HTTP/2 200
curl -sI https://example.com | head -1

# ต้องรายงานว่าต่อฐานข้อมูลได้
curl -s https://example.com/api/health

# พิมพ์ http ต้องถูกผลักไป https
curl -sI http://example.com | grep -i location
```

เปิดเบราว์เซอร์แล้วต้องขึ้นแม่กุญแจ ไม่มีคำเตือนเรื่องใบรับรอง
